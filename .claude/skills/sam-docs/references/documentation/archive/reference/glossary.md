# Glossary

This page is the canonical place to look up a term that appears in any other page of this site. Terms are listed alphabetically.

| Term | Definition |
|---|---|
| **A2A** | Agent-to-Agent protocol. The JSON-RPC 2.0 wire format agents use to talk to each other over the broker. Wire-compatible with the Python implementation. See Concepts → A2A protocol. *Avoid: agent protocol, inter-agent protocol.* |
| **Agent** | An LLM-driven worker, declared in YAML, that processes messages by calling tools and (optionally) delegating to other agents. At the AWE/YAML layer, `agent_type` is `standard` (LLM loop + tool calls) or `workflow` (DAG execution without tool calling). See Concepts → Configured vs built. *Avoid: bot, assistant, model.* |
| **Agent card** | The self-describing record an agent publishes on the discovery topic at startup (and republishes when its capability set changes). Carries the agent's name, description, model, skills, and protocol features. Gateways publish an analogous gateway card on the same discovery topic family. *Avoid: agent manifest, agent descriptor, agent metadata blob.* |
| **Artifact** | A versioned blob (document, image, data set) produced or consumed by an agent. Versioning is by integer sequence, exposed as `data_version` and `metadata_version`. Backends: filesystem, S3, GCS, Azure Blob Storage, in-memory. See Concepts → Artifacts. *Avoid: file, blob, asset, attachment, revision, generation.* |
| **Artifact handling mode** | The per-agent setting (`artifact_handling_mode`) that governs how tool-produced artifacts surface in the conversation history. Values: `ignore` (default — no inline summary), `embed` (artifact content embedded inline), `reference` (URI reference only). *Avoid: artifact mode, artifact projection mode.* |
| **Artifact scope** | The per-component setting (`artifact_scope`) that determines whether artifacts are partitioned by namespace or by component. `namespace` (default) places artifacts under the app's namespace, letting agents in the same namespace share them. Distinct from the in-filename user-scope opt-in (the `user:` filename prefix), which is an addressability concern. *Avoid: artifact partition.* |
| **AWE** | Agent-Workflow Executor. The process that loads agent configs, runs the LLM loop, and dispatches tool calls. See Concepts → GWE, AWE, STR. *Avoid: agent runtime, agent executor.* |
| **Broker** | The transport that realises the event mesh. Production is Solace PubSub+; local development uses the dev broker or the in-memory broker. *Avoid: messaging service, message broker.* |
| **Built tool** | A tool implemented as a standalone binary the Secure Tool Runtime spawns — Go using `pkg/samtoolsdk`, or Python using `sam-tool-sdk`. The customer authoring path for behaviour the YAML tool taxonomy can't express. See Concepts → Configured vs built. *Avoid: custom tool, native tool, code tool.* |
| **Community** | Legacy. Agent Mesh no longer ships as a split Community / Enterprise product. Treat it as one product with one feature surface (authentication, RBAC, the platform service, every connector, and every gateway included). Customer-facing prose should not gate features as "Community-only". *Avoid: Community tier, (Community), Community edition, community-tier install track.* |
| **Compaction percentage** | The post-compaction history size as a fraction of the pre-compaction conversation. The `auto_summarization.compaction_percentage` YAML key (default `0.25` — 25% of the conversation gets compacted into the summary). The manual-compaction endpoint exposes the same dial as `targetPercent`. *Avoid: compaction ratio, summary ratio.* |
| **Configured agent** | An agent defined entirely in YAML, including its tool list and any embedded prompts. The only customer authoring path for agents on the Go surface; emphasised when contrasting with a built tool that the agent calls. Synonymous in code with `agentType: standard` plus a YAML config file. See Concepts → Configured vs built. *Avoid: declarative agent, YAML agent.* |
| **Correlation ID** | A per-hop UUID that matches an outstanding request to its response — distinct from a trace ID (one per user task, immutable) and a task ID (gateway-minted user task addressing). Surfaces in logs as `corrID` or `reqID`. *Avoid: using "correlation ID" interchangeably with "trace ID"; using "request ID" without context.* |
| **Declarative config** | The YAML resources passed to `sam config apply` and reconciled against the Platform service. A directory laid out by kind, with a top-level `manifest.yaml` that names the target and lists resources. Distinct from runtime config, which is read directly by the binary. *Avoid: platform config, API config, applied config, spec-driven config.* |
| **Default behavior** | The per-`session_service` setting (`default_behavior`) that governs whether sessions survive the end of a task. Values: `PERSISTENT` (the row survives — the shipped default for every gateway type) and `RUN_BASED` (the row is bounded to a single task). See Concepts → Sessions. *Avoid: session mode, persistence mode.* |
| **Deployment** | A running instance of a project. The Platform service tracks deployments as first-class resources. *Avoid: instance, stack.* |
| **Desktop mode** | A Wails v2 native window that wraps embedded mode. Same component layout, plus a UI. Launched by running the desktop-tagged `sam` binary with no arguments (typically shipped as `sam-desktop`). There is no `--desktop` flag. *Avoid: GUI mode, app mode.* |
| **Dev broker** | The TCP broker for local development. Use "dev broker" in prose, `devbroker` only when referring to the literal binary name. The same implementation also runs in-process inside embedded mode, desktop mode, and tests — when there is no TCP listener, refer to it as the in-memory broker. *Avoid: local broker, test broker.* |
| **Distributed deployment** | Separate processes for AWE, gateway, STR, and an external broker. Used in production. A phrase, not a noun — say "a distributed deployment" or "production deployment". *Avoid: production mode, standalone mode.* |
| **Embed** | A `«type:params»` token that the runtime substitutes with content drawn from elsewhere — most commonly an artifact reference (`«artifact_content:report.md»`), a status update, or a templated value. Operators tune the resolver via `enable_embed_resolution` and `gateway_artifact_content_limit_bytes`. *Avoid: macro, placeholder, template tag, embed grammar.* |
| **Embedded mode** | A single-process layout where AWE, the gateway, STR, and an in-memory dev broker run as goroutines together. Invoked with `sam run --embedded`. *Avoid: CLI mode, single-binary mode, all-in-one mode.* |
| **Enterprise** | Legacy. Agent Mesh no longer ships as a split Community / Enterprise product. Treat it as one product with one feature surface. Customer-facing prose should not gate features as "Enterprise-only" — describe the feature directly. *Avoid: Enterprise tier, Enterprise-only, Enterprise SKU, Enterprise feature.* |
| **Event mesh** | The conceptual fabric of topics over which agents, gateways, and tools communicate. The fabric is provided by a broker. See Concepts → Event-driven mesh. *Avoid: message bus, messaging layer, pubsub layer.* |
| **Gateway** | The HTTP-and-broker bridge that fronts AWE — a role, not a process. Carries user-facing concerns: SSE streaming, sessions, auth, web UI. Wire-level `type` values: `httpsse`, `eventmesh`, `slack`, `email`, `mcp`, `teams`. The long-running process that hosts one or more gateways is GWE. *Avoid: API gateway, HTTP gateway, frontend, conflating gateway (role) with GWE (process).* |
| **GWE** | Gateway Executor. The workload class — the long-running process you operate, scale, and probe — that hosts one or more gateways. The third member of the workload-class trio alongside AWE and STR. See Concepts → GWE, AWE, STR. *Avoid: the gateway process, gateway pod / gateway container (when the workload class is meant).* |
| **History compaction** | The runtime's mechanism for keeping a conversation inside the model's context window: when continued history would exceed the budget, an extra LLM call summarises older messages into a single replacement and the loop retries with smaller history. Two modes: reactive auto-compaction and manual compaction (via `POST /api/v1/sessions/{id}/compact`). *Avoid: summarisation, history truncation, context pruning.* |
| **IdP** | Identity provider. Spell as "IdP" (capital I, lowercase d, capital P) after first-use expansion. *Avoid: SSO provider, OAuth provider, auth provider.* |
| **Manifest** | The `kind: manifest` document at the root of a declarative config tree. Names the Platform service target, declares variables, and lists which resources to apply. Distinct from a skill's `SKILL.md` and from the tool manifest STR uses. *Avoid: bundle file, apply file, config root.* |
| **Namespace** | The configurable first segment of every A2A topic — set per app in `app_config.namespace`, default `solace-agent-mesh`. A single Solace event mesh can carry multiple independent Agent Mesh deployments by giving each one a distinct namespace. *Avoid: tenant, prefix (alone), environment.* |
| **Orchestrator agent** | A role, not a type. An agent that delegates to other agents via the A2A protocol rather than executing tools itself. Conventionally named `Orchestrator` in examples. *Avoid: orchestrator (alone), router agent, dispatcher.* |
| **Peer agent** | An agent that another agent delegates to over the A2A protocol. The relationship is described from the perspective of the delegating agent. *Avoid: remote agent, external agent, delegate agent.* |
| **Persistent** | One of the two values of `default_behavior`. Persistent sessions outlive the task and load prior history on the next turn under the same session key. Capitalise as a proper noun when discussing the value (wire spelling `PERSISTENT`); lowercase in adjective form ("a persistent session"). *Avoid: stateful.* |
| **Platform service** | The HTTP service that exposes agents, deployments, projects, evaluations, toolsets/skills, model configuration, RBAC/identity, MCP integrations, audit logs, and the AI assistant. Always two words; the first is lowercase unless it starts a sentence. See Concepts → Platform service. *Avoid: Agent Mesh Platform, the Platform (alone), platform (alone in prose).* |
| **Project** | A directory containing the configuration for one Agent Mesh deployment. Newer projects are declarative-config repos rooted at `manifest.yaml`; legacy projects use a `configs/` + `src/` + `.env` layout consumed by `sam run`. *Avoid: config bundle, workspace.* |
| **RBAC** | Role-Based Access Control. Expand on first use. |
| **Role provider** | The component that maps a user (post-authentication) to roles. The only implementation today is `idp_claims` (maps IdP-issued OIDC claim values to roles); SCIM provisioning is on the roadmap but not yet implemented. *Avoid: permission provider, claim mapper, role resolver, documenting `scim` as a working option.* |
| **Run-based** | One of the two values of `default_behavior`. Run-based sessions are bounded to one task and not reused afterwards — the right choice for one-shot transformations. Wire spelling `RUN_BASED`. Sub-task delegations propagate `sessionBehavior: RUN_BASED` so callees get a clean slate even when the caller is persistent. *Avoid: stateless, ephemeral.* |
| **Runtime config** | The YAML files passed to `sam run`, AWE, the gateway, or the STR worker at startup. Declares the broker, models, and the list of `apps` (one per component). Read directly by the binary — no Platform service in the path; each component reads its own runtime config. Distinct from declarative config, which is reconciled through `sam config apply`. *Avoid: static config, boot config, process config, runtime YAML (use "runtime config" consistently).* |
| **sam CLI** | The command-line tool (the `sam` binary) that runs the embedded orchestrator or desktop app (`sam run`), executes tasks (`sam task`), manages declarative config (`sam config`, `sam toolset`, `sam skill`), runs evaluations (`sam eval`), and handles authentication (`sam auth`). *Avoid: the CLI (alone).* |
| **sam-go** | The Go implementation of Agent Mesh; the subject of this repository. Use in prose when distinguishing it from the Python implementation. *Avoid: alternate hyphenations of the name; `solace-agent-mesh-go` (the repo slug, not a prose term).* |
| **Session** | The persisted conversation between a user and an agent, including message history, task checkpoints, and metadata. Backed by SQLite, Postgres, or in-memory. See Concepts → Sessions. *Avoid: conversation (as the canonical term), thread, history.* |
| **Session key** | The identifier the gateway derives from its inbound transport to look up (or create) a session row. Each gateway type has its own derivation: Web UI uses an explicit `sessionID`; Slack uses `(channel, thread_ts)`; Email uses the `References` thread root; Teams uses `convID` plus tenant; MCP uses the OAuth identity; Event Mesh derives the key from `input_expression` or user properties. *Avoid: session ID (interchangeably), conversation key, thread ID.* |
| **Skill** | An agentskills.io-style bundle (`SKILL.md` instructions plus optional `references/`, `assets/`, and `tools/`) that an agent loads on demand via `load_skill`. Managed as a Platform resource — uploaded through the Skills page or `/api/v1/platform/skills`, with a `discoveryStatus` lifecycle, attached to agents via `skillIds` / `skillRefs`. Agent Mesh uses `tools/` in place of the agentskills.io `scripts/` directory. See Concepts → Skills. *Avoid: calling a skill a "toolset" (a toolset is the separate always-on packaging resource), plugin, tool bundle (use "skill bundle" only as a synonym for the directory containing a SKILL.md).* |
| **Soft-subset assert** | The JWT trust manager's reconciliation rule: the unsigned tool or capability claims in a message body are accepted only if they are a subset of the cryptographically signed claims on the bearer JWT. Narrowing is allowed; widening is dropped with a structured warning. *Avoid: claim subset check, JWT narrowing.* |
| **Solace Agent Mesh** | The product. Use the full name on first reference in customer-facing docs; after that, "Agent Mesh" is the accepted short form. Do not abbreviate it to the three-letter acronym in customer-facing prose. *Avoid: the platform, the product, the mesh, the bare three-letter acronym in customer-facing prose.* |
| **Solace PubSub+** | The production broker product. Spell it exactly this way (no space before "+"; no "Solace PubSub Plus"). *Avoid: Solace broker, PubSub+, Solace messaging.* |
| **SSO** | Single sign-on. The OIDC flow the gateway uses for browser-based login. *Avoid: single signon, single-sign-on.* |
| **STR** | Secure Tool Runtime. The sandboxed process that executes tools — both Python script tools and Go tool binaries. See Concepts → GWE, AWE, STR. *Avoid: tool runtime, tool bridge, sandbox.* |
| **Tool** | A discrete capability an agent can invoke. The wire-level `tool_type` values in YAML are `builtin`, `builtin-group`, `mcp`, and `openapi`. Non-wire categories in prose: "built-in tool" (runs inside AWE), "MCP tool", "OpenAPI tool", "remote tool" (Python script or Go binary running inside STR), and "skill-bundled tool". *Avoid: plugin, function, action, `tool_type: remote` / `tool_type: skill` (neither exists as a wire value).* |
| **Tool manifest** | The `tools/manifest.yaml` (or equivalent) that declares the tools STR hosts in a skill bundle — name, description, parameter schema, and the binary or script that backs each tool. STR parses tool manifests at startup and broadcasts the available toolset so AWE knows what is callable. Distinct from Manifest (the `kind: manifest` declarative-config root). *Avoid: tool spec, tool descriptor, tool catalog.* |
| **Toolset** | A Platform-managed, independently-deployable package of remote tools. Authored with `sam toolset init`, built and zipped with `sam toolset package`, uploaded through the Platform service (the Toolsets web UI or `/api/v1/platform/toolsets`), and attached to agents by name. Has a `discoveryStatus` lifecycle (`created` → `pending` → `ready` / `failed`, plus `removed`). See Concepts → Toolsets. *Avoid: tool package, plugin, conflating a toolset (Platform packaging) with a skill (a `SKILL.md` bundle).* |
| **Topic** | A hierarchical broker address under `<namespace>/a2a/v1/<service>/...` (where `<namespace>` is the configurable broker namespace, for example, `solace-agent-mesh`) that agents publish or subscribe to. Always use the full path when citing a specific topic. *Avoid: channel, queue, `solace-agent-mesh/v1/...` (wrong prefix).* |
| **Trace ID** | An immutable UUIDv7 minted by the gateway when a user task is submitted, then propagated end-to-end on every A2A message hop. A single `grep traceID=<uuid>` (or `@traceID:<uuid>` in Datadog Logs) surfaces the full causal chain across gateway, agent, STR, and tool logs. One per user task, never re-minted on republish. Not a distributed-tracing span. *Avoid: correlation ID, request ID, span ID, OTel trace ID.* |
| **Workflow** | A DAG of typed nodes executed by AWE. The valid node types are `agent`, `tool`, `switch`, `map`, `loop`, and `workflow` (nested). Workflows are a distinct concept from agents — a `workflow`-type agent runs a workflow, but a workflow is not itself an agent. *Avoid: pipeline, DAG (in prose).* |
